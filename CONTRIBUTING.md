# Research contributions

Please review the proprietary LICENSE and obtain the required permission before using or contributing derivative work. This guide does not grant an additional license.

For a documentation correction or authorized contribution, use a focused pull request and explain the problem, change and verification. Preserve existing authorship and attribution.

For an experiment, include the notebook or script, commit SHA, data version, split IDs, class mapping, preprocessing, seed, dependency versions and hardware. Report validation-based model selection separately from held-out test evaluation. Label saved historical results and newly rerun results clearly; include repeated trials when making comparative claims.

Do not commit raw datasets, private manuscript files, credentials or large trained weights. Keep external resources under their own terms. Small representative diagnostics and machine-readable metric summaries are preferable to large regenerated notebook output dumps.

Repository issues may be disabled on this fork. Use an available pull-request channel for focused code/documentation changes, or the repository owner's public professional links for research inquiries.
